# 레드스톤 논리회로 실험실

마인크래프트식 3D 복셀 공간에서 **레드스톤으로 논리회로를 설계**하는 수업용 웹 게임입니다.
영재학급 «디지털 논리회로의 설계» (100분 × 2일) 수업용으로 만들었습니다.

학생은 **미션**을 하나씩 통과하며 올라갑니다. 각 미션은 목표 **진리표**를 주고,
회로를 고칠 때마다 **모든 입력 조합을 자동으로 돌려 실시간 채점**합니다.
학생이 따로 누를 것은 없습니다. 통과해야 다음 미션이 열립니다.

**바로 열기: <https://banatic.github.io/redstone-logic-lab/>**

* 학생은 위 주소로 접속하면 됩니다. 설치할 것 없음.
* `index.html` 을 내려받아 더블클릭해도 열립니다 (인터넷이 없으면 글꼴만 맑은 고딕으로 바뀝니다).
* three.js 는 저장소 안에 들어 있고, 글꼴(Pretendard)만 jsDelivr CDN 에서 받습니다.

## 0. 실행하기

### 학생은 주소로 접속

<https://banatic.github.io/redstone-logic-lab/> — `main` 브랜치를 그대로 GitHub Pages 로 내보냅니다.
저장소에 push 하면 1~2분 뒤에 반영됩니다.

### 파일로도 열립니다

`index.html` 은 three.js 를 포함한 모든 코드가 들어 있는 **단일 파일**입니다.
서버 없이 더블클릭으로 열리므로 USB 로 나눠 줘도 됩니다.

### 코드를 고칠 때

`index.html` 은 **자동 생성 파일이라 직접 고치지 마세요.**
원본은 `dev.html` + `js/` + `css/` 이고, 고친 뒤 다시 빌드하면 `index.html` 이 갱신됩니다.

```bash
node tools/build.mjs
```

`dev.html`(ES 모듈 버전)로 개발하려면 로컬 서버가 필요합니다.

> ⚠️ `dev.html` 을 탐색기에서 더블클릭하면 열리지 않습니다.
> 브라우저는 `file://` 을 "출처 없음"으로 취급해서 ES 모듈 로딩을 CORS 로 막습니다.
> 코드 문제가 아니라 브라우저 보안 정책입니다. 그래서 배포용 `index.html` 을 단일 파일로 만들어 둔 것입니다.

```bash
python -m http.server 8123
```

그리고 `http://localhost:8123/dev.html` 로 접속합니다.

## 1. 미션 사다리

| # | 미션 | 새로 배우는 것 | 쓸 수 있는 블럭 |
|---|---|---|---|
| **1일차** |
| 1 | 레버와 램프 잇기 | 조작 익히기 | 와이어 |
| 2 | 멀리 있는 램프 켜기 | 신호 감쇠 → 리피터 | 와이어, 리피터 |
| 3 | NOT 게이트 | 토치 = 인버터 | 블럭, 와이어, 토치 |
| 4 | OR 게이트 | 합치기만 하면 OR | 와이어 |
| 5 | NOR 게이트 | OR + NOT | 블럭, 와이어, 토치 |
| 6 | 고장난 회로 고치기 | 절연체 · **디버깅** | 블럭, 유리, 와이어, 토치 |
| 7 | NAND 게이트 | 드모르간 | 블럭, 와이어, 토치 |
| 8 | AND 게이트 | 인버터 3개 | 블럭, 와이어, 토치 |
| **2일차** |
| 9 | XOR 게이트 | NOR 4개 + 인버터, 팬아웃 | 전부(레버·램프 제외) |
| 10 | 반가산기 | 출력 2개 (합·올림) | 전부(레버·램프 제외) |
| 11 | 가감산기 | 모드 레버로 덧셈 ↔ 뺄셈 | 전부(레버·램프 제외) |
| 12 | 전가산기 ★ | 심화 | 전부(레버·램프 제외) |

### 설계 의도

* **레버와 램프는 미리 놓여 있고 부술 수 없습니다.** 학생은 그 사이만 채웁니다.
* **미션마다 쓸 수 있는 블럭이 제한됩니다.** 레드스톤 블럭·레버·램프를 빼 두었기 때문에
  "램프 옆에 전원을 붙여 켜기" 같은 우회가 불가능합니다. 진리표를 통과하는 길은 회로뿐입니다.
* **6번은 만들기가 아니라 고치기입니다.** NAND 회로 한 곳의 일반 블럭이 유리로 바뀌어 있어
  진리표의 **마지막 한 줄만** 틀립니다. "어느 줄이 틀렸나 → 그럼 어디를 봐야 하나"를
  스스로 좁혀 들어가게 하는 미션입니다. 새로 만드는 것보다 사고 부하가 높고 소요 시간은 예측 가능해서,
  진도 조절 밸브로도 씁니다.
* **11번 가감산기**는 모드 레버 하나로 덧셈과 뺄셈을 겸하는 회로입니다.
  결과는 모드와 무관하게 `A ⊕ B` 이고, 자리 신호만 `A·B`(올림) 와 `¬A·B`(빌림) 사이에서 바뀝니다.
  둘을 합치면 `자리 = B · (A ⊕ 모드)` — 이걸 학생이 찾아내는 것이 이 미션의 핵심입니다.
  12번 전가산기보다 쉬워서 앞에 두었습니다.
* **필수 도달선은 4번(OR)**, 표준은 6번, 7~8번은 심화입니다. 앞이 느려도 수업이 무너지지 않습니다.
* **1일차 미션과 9번(XOR)은 언제나 열려 있습니다.** 컴퓨터실 PC 는 껐다 켜면 초기화되어
  1일차 진도가 남아 있지 않기 때문입니다. 10·11번만 앞 미션을 통과해야 열립니다.
* **블럭 수가 기록됩니다.** 통과할 때마다 최소 기록이 갱신되므로,
  빨리 끝낸 학생에게는 "같은 진리표를 더 적은 블럭으로"를 계속 줄 수 있습니다.

## 2. 화면

### 미션 패널 (오른쪽 위)

```
NOT 게이트      통과  블럭 7

 A │ 램프
 0 │  1   ✓      ← 지금 레버 상태인 줄이 강조됩니다
 1 │  0   ✓
```

목표 진리표와 학생이 놓은 블럭 수. 그게 전부입니다.
설명은 넣지 않았습니다. **설명은 선생님이 합니다.**

블럭을 놓거나 부술 때마다 모든 입력 조합을 자동으로 돌려 각 줄에 ✓/✗ 를 찍습니다.
**어느 줄이 아직 틀렸는지 만드는 내내 보입니다.** 전부 맞으면 램프색 **통과** 표시가 붙고
다음 미션이 열립니다.

### 회로 참고 (오른쪽)

`회로 참고` 버튼을 누르면 오른쪽에 **기본 게이트 기호**(AND·OR·NOT·XOR·NAND·NOR)와
**반가산기·가감산기·전가산기의 식과 설계도**가 나옵니다. **그 세 미션에 들어가면 저절로 펼쳐집니다**
(직접 닫으면 그 뒤로는 펼치지 않습니다).

여기 있는 것은 **논리 수준의 설계도**이지 레드스톤 배선이 아닙니다.
`합 = A ⊕ B` 를 알아도 XOR 을 레드스톤으로 만드는 일은 그대로 남아 있습니다.

## 3. 블럭 구성

| 블럭 | 역할 |
|---|---|
| 일반 블럭 | **전도체.** 신호를 담을 수 있어 회로를 위·아래로 옮기거나 토치를 붙이는 데 씁니다 |
| 비전도 블럭 (유리) | **절연체.** 절대 충전되지 않습니다 |
| 레드스톤 와이어 | 신호가 흐르는 선. 한 칸마다 세기가 1씩 줄어듭니다 |
| 레드스톤 블럭 | 항상 켜져 있는 세기 15 전원 |
| 레드스톤 램프 | 출력 표시등 |
| 리피터 | 신호 증폭(15로 복원) + 한 방향 통과(다이오드) + 1~4틱 지연 |
| 레버 | **입력 스위치** (우클릭으로 켜고 끄기) |
| 레드스톤 토치 | **인버터(NOT).** 붙어 있는 블럭이 충전되면 꺼집니다 |

미션 중에는 이 중 필요한 것만 핫바에 나옵니다. 내 작업장에서는 전부 쓸 수 있습니다.

## 4. 조작법

단축키를 외우지 않아도 되게 만들었습니다. **회로를 만드는 데 필요한 조작은 전부 마우스**이고,
화면 이동만 키보드를 씁니다. 채점·맵 이동·도움말은 화면의 버튼으로 합니다.

| 마우스 | 동작 |
|---|---|
| 왼쪽 클릭 | 블럭 부수기 |
| 오른쪽 클릭 | 블럭 놓기 · 레버 켜고 끄기 · **리피터 방향 돌리기** |
| 가운데 클릭 | 보고 있는 블럭 고르기 |
| 휠 | 블럭 선택 (화면 아래 칸을 눌러도 됩니다) |
| 드래그 | 시점 돌리기 |

| 키보드 | 동작 |
|---|---|
| W A S D | 이동 |
| **W 두 번** | **달리기** (W 를 놓으면 풀립니다) |
| Space | 점프 · (비행 중) 위로 |
| **Space 두 번** | **비행 ↔ 걷기** |
| Shift | 아래로 |
| Ctrl | 빠르게 (누르고 있는 동안) |

> 리피터는 **바라보는 방향으로 놓이고**, 우클릭으로 방향을 돌립니다.
> 지연(1~4틱)은 수업에서 쓸 일이 없어 `R` 키로 내려두었습니다. 클럭·지연 예제 시연용입니다.
> 비행 전환과 달리기는 마인크래프트와 같습니다. **점프 두 번**으로 비행 ↔ 걷기,
> **W 두 번**으로 달리기(비행 중에는 빠른 비행)입니다. 처음에는 비행 상태로 시작합니다.
> 그 밖에 `H` 도움말, `B` 내 작업장, `P`/`T` 일시정지·한 틱, `Esc` 메뉴가 있지만
> 모두 화면 버튼이나 메뉴로도 됩니다.

학교 PC 처럼 **마우스 잠금(Pointer Lock)이 막힌 브라우저**에서는 자동으로
드래그 모드로 동작합니다. 화면을 끌면 시점이 돌고, 짧게 클릭하면 블럭을 다룹니다.

화면 왼쪽 위에 조준 중인 블럭의 **신호 세기가 15칸 막대**로 실시간 표시됩니다.
미션의 레버와 램프에는 `레버 A` `램프 합` 처럼 이름이 붙어 나옵니다.
신호가 왜 안 가는지 학생이 스스로 찾아내게 하는 데 이 표시가 제일 쓸모 있습니다.

## 5. 시뮬레이션 규칙 (교육용으로 단순화)

1. 신호 세기는 **0~15**. 와이어를 한 칸 지날 때마다 **1씩 감소**합니다.
2. 세기 15 전원: **레드스톤 블럭, 켜진 레버, 켜진 토치, 켜진 리피터의 출력**
3. 블럭의 충전에는 두 종류가 있습니다.
   * **강한 충전** — 토치 *바로 위* 블럭 / 레버가 붙은 블럭 / 리피터가 바라보는 블럭.
     강하게 충전된 블럭은 맞닿은 와이어를 다시 15로 만듭니다.
   * **약한 충전** — 와이어가 *가리키는* 블럭과 와이어 *아래* 블럭.
     램프·리피터·토치는 작동시키지만 다른 와이어로 흘러나가지는 않습니다.
4. **비전도 블럭과 바닥판은 절대 충전되지 않습니다.**
5. **토치는 자기가 붙은 블럭이 충전되면 꺼집니다** → NOT 게이트.
6. 토치는 1틱, 리피터는 1~4틱 지연됩니다. 그래서 **클럭(발진 회로)** 이 만들어집니다.

조준 판정은 블럭의 **실제 생김새**를 씁니다. 와이어는 납작한 판, 리피터는 낮은 판이라
그 위를 스쳐 지나는 시선은 가로채지 않고 너머 바닥이 잡힙니다.
강조 상자도 그 크기로 나오므로 무엇을 조준 중인지 바로 보입니다.

> 와이어가 앞쪽 일반 블럭을 충전하려면 그 와이어가 **직선**이어야 합니다.
> T 자로 갈라진 와이어는 옆으로만 연결되고 앞 블럭은 가리키지 않습니다.
> 회로가 안 될 때 자주 걸리는 지점이니 알아 두세요.

## 6. 박물관

미션과 별개로 **구경만 하는 큰 회로**들이 있습니다. 메뉴의 `박물관`.
블럭을 놓거나 부술 수 없고(핫바가 비어 있습니다) **레버만 만질 수 있습니다.**

| 전시물 | 크기 | 무엇을 보나 |
|---|---|---|
| **7세그먼트 숫자 표시기** | 블럭 2,410개 · 85 x 58 | 레버 네 개(1 2 4 8)로 만든 2진수 0~9 를 숫자 모양으로 켭니다 |
| **2비트 곱셈기** | 블럭 1,668개 | A 와 B 를 0~3 으로 놓으면 곱을 2진수로 켭니다 |
| **2비트 비교기** | 블럭 2,853개 | A 와 B 중 어느 쪽이 큰지 램프 하나로 답합니다 |
| 리피터 지연 비교 · 클럭 · 절연체 · RS 래치 | 작음 | 진리표로 채점할 수 없는 회로들 |

앞의 세 개는 **손으로 배선한 것이 아니라 코드가 찍어낸 것**입니다(`js/museum.js`).
실제 칩과 같은 격자 배치(PLA)로, 규칙 두 개만으로 만들어집니다.

* 배선이 교차해야 하므로 **2층**으로 나눕니다. 아래층은 가로줄, 위층(블럭 위)은 세로 버스.
  가로줄은 버스 밑을 그냥 지나갑니다.
* 버스에서 가로줄로 신호를 내리는 **탭**은 버스 받침 블럭에 붙인 토치입니다.
  버스가 켜지면 받침이 충전되어 토치가 꺼지므로, **탭은 신호를 뒤집어** 내려보냅니다.
  그래서 `가로줄 = OR(탭한 신호들의 반전)` 이 되고, 이것만으로 2단 PLA 가 완성됩니다.

신호가 표시기까지 도달하는 데 **15~17틱**이 걸립니다. 레버를 젖히면 회로를 타고
번져 가는 것이 눈으로 보입니다. 수업에서는 이게 제일 볼거리입니다.

### 그 밖의 맵

* **미션 맵** — 미션마다 독립된 공간. 만들던 것은 그대로 남고 브라우저에 자동 저장됩니다.
* **내 작업장** — 아무 제한 없이 자유롭게 만드는 공간.

미션의 정답에 해당하는 게이트 회로는 사이트 어디에도 없습니다 (소스에도 없습니다).

### 제출

메뉴 → `제출, 저장, 설정` → **이름을 적고 파일로 내보내기**.
`이름_circuit.json` 에 지금 회로와 **통과한 미션·블럭 수 기록**이 함께 담깁니다.
교사 PC 에서 **파일 열기**로 확인할 수 있습니다.

### 교사용

같은 메뉴 안에 있습니다.

* **모든 미션 열기** — 잠금을 무시하고 아무 미션이나 열 수 있게 합니다. 시연·보충용.
* **진행 상황 지우기** — 통과 기록을 초기화합니다. 다음 반이 쓰기 전에 누르세요.

```
index.html            ★ 배포·실행용 단일 파일 (자동 생성. 직접 고치지 말 것)

```

### 미션 추가하기

`js/missions.js` 의 `MISSIONS` 배열에 한 덩이를 더하면 됩니다.

```js
{
  id: 'xnor', day: 2, title: 'XNOR 게이트',
  inputs: [[0, 0, 0], [0, 0, 4]],     // 레버 위치 (자동으로 놓이고 잠깁니다)
  outputs: [[10, 0, 2]],              // 램프 위치
  truth: [[1], [0], [0], [1]],        // 레버 비트마스크 순서 (bit0 = A)
  allowed: GATE,                      // 핫바에 나올 블럭
  start: [],                          // 미리 놓아 둘 블럭 (디버깅 미션용)
}
```

정답 회로는 `tools/solutions.mjs` 의 `SOLUTIONS` 에 같은 id 로 넣습니다. 배포 파일에는 실리지 않습니다.

`node tools/test-missions.mjs` 가 **정답 회로는 통과하는지**와
**시작 상태는 통과하지 않는지**(= 과제가 성립하는지)를 둘 다 확인해 줍니다.
